# 12 — Storage Schema (SQLite)

One SQLite file per product (`cow.db`). All amounts/scores stored as **TEXT** (decimal
strings of `U256`) — SQLite has no 256-bit integer type and we must not lose precision.
Floats (`gap_ratio`, `abs_rel_error`) are stored as `REAL` for convenience in reporting
only.

Migrations live in `apps/cow-shadow-solver/migrations/` and are run by
`storage::migrations` via `sqlx::migrate!`.

## `migrations/0001_init.sql`

```sql
-- Raw API payloads (audit trail; lets us re-derive everything offline)
CREATE TABLE raw_auctions (
    auction_id      INTEGER PRIMARY KEY,
    block           INTEGER NOT NULL,
    fetched_at      TEXT    NOT NULL,         -- ISO8601 UTC
    payload_json    TEXT    NOT NULL          -- full AuctionSnapshot JSON
);

CREATE TABLE raw_solver_competitions (
    auction_id      INTEGER PRIMARY KEY,
    auction_block   INTEGER NOT NULL,
    fetched_at      TEXT    NOT NULL,
    winner_address  TEXT,
    winner_score    TEXT,                     -- U256 decimal string
    payload_json    TEXT    NOT NULL          -- full SolverCompetition JSON
);

-- Normalized orders seen per auction
CREATE TABLE normalized_orders (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    auction_id      INTEGER NOT NULL,
    order_uid       TEXT    NOT NULL,
    sell_token      TEXT    NOT NULL,
    buy_token       TEXT    NOT NULL,
    sell_amount     TEXT    NOT NULL,         -- atoms, U256 string
    buy_amount      TEXT    NOT NULL,
    kind            TEXT    NOT NULL,         -- 'sell' | 'buy'
    class           TEXT    NOT NULL,         -- 'market'|'limit'|'liquidity'
    partially_fillable INTEGER NOT NULL,      -- 0/1
    supported       INTEGER NOT NULL,         -- 0/1
    skip_reason     TEXT,
    created_at      TEXT    NOT NULL,
    UNIQUE(auction_id, order_uid)
);

-- The scorer validation gate results (the most important table)
CREATE TABLE winner_score_validations (
    auction_id          INTEGER PRIMARY KEY,
    api_winner_score    TEXT    NOT NULL,      -- U256 string
    recomputed_score    TEXT    NOT NULL,      -- U256 string
    abs_rel_error       REAL    NOT NULL,
    within_tolerance    INTEGER NOT NULL,      -- 0/1 (<= 0.01)
    contains_buy_orders INTEGER NOT NULL,      -- bucket flag
    contains_partial    INTEGER NOT NULL,      -- bucket flag
    multi_pair          INTEGER NOT NULL,      -- bucket flag
    notes               TEXT,
    created_at          TEXT    NOT NULL
);

-- Candidate routes generated by the engine (post-gate)
CREATE TABLE route_candidates (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    auction_id      INTEGER NOT NULL,
    order_uid       TEXT    NOT NULL,
    venue           TEXT    NOT NULL,         -- 'cow_quote'|'univ2_direct'|'univ2_two_hop'
    amount_in       TEXT    NOT NULL,
    amount_out      TEXT    NOT NULL,
    gas_estimate    INTEGER NOT NULL,
    ok              INTEGER NOT NULL,         -- 0/1
    chosen          INTEGER NOT NULL,         -- 0/1 best-per-order
    score_native    TEXT,                     -- U256 string (null if not scored)
    risk_score      INTEGER,
    risk_band       TEXT,
    ebbo_violation  INTEGER,                  -- 0/1
    flags           TEXT,                     -- json array of strings
    created_at      TEXT    NOT NULL
);

-- Quote call results (latency + reliability analysis)
CREATE TABLE quote_results (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    auction_id      INTEGER NOT NULL,
    order_uid       TEXT    NOT NULL,
    venue           TEXT    NOT NULL,
    amount_out      TEXT,
    ok              INTEGER NOT NULL,
    latency_ms      INTEGER NOT NULL,
    error           TEXT,
    created_at      TEXT    NOT NULL
);

-- Per-auction competitiveness grade (my score vs winner score)
CREATE TABLE auction_comparisons (
    auction_id      INTEGER PRIMARY KEY,
    my_total_score  TEXT    NOT NULL,
    winner_score    TEXT    NOT NULL,
    gap_ratio       REAL    NOT NULL,         -- (winner-mine)/winner; negative => we beat
    tag             TEXT    NOT NULL,         -- 'competitive'|'marginal'|'not_competitive'
    created_at      TEXT    NOT NULL
);

-- Daily aggregates for the report
CREATE TABLE daily_rollups (
    date                TEXT PRIMARY KEY,     -- YYYY-MM-DD UTC
    auctions_seen       INTEGER NOT NULL,
    gate_attempts       INTEGER NOT NULL,
    gate_passed         INTEGER NOT NULL,
    competitive         INTEGER NOT NULL,
    marginal            INTEGER NOT NULL,
    not_competitive     INTEGER NOT NULL,
    p50_gap_ratio       REAL,
    p95_gap_ratio       REAL,
    updated_at          TEXT NOT NULL
);

-- Indexes
CREATE INDEX idx_norm_auction      ON normalized_orders(auction_id);
CREATE INDEX idx_norm_uid          ON normalized_orders(order_uid);
CREATE INDEX idx_routes_auction    ON route_candidates(auction_id);
CREATE INDEX idx_routes_uid        ON route_candidates(order_uid);
CREATE INDEX idx_quotes_auction    ON quote_results(auction_id);
CREATE INDEX idx_val_tolerance     ON winner_score_validations(within_tolerance);
CREATE INDEX idx_cmp_tag           ON auction_comparisons(tag);
```

## Writer conventions

- **Append-only** for raw + per-auction tables; never UPDATE history. `daily_rollups` is
  the only table that gets UPSERTed (recomputed at report time).
- All writes go through `storage`'s typed helpers; the app never writes raw SQL inline
  (keeps migrations and queries auditable).
- Use a single `SqlitePool` with WAL mode (`PRAGMA journal_mode=WAL`) for concurrent
  read during write. Set `PRAGMA synchronous=NORMAL` (durable enough for a logger,
  faster than FULL).
- Wrap per-auction persistence (raw + normalized + candidates + comparison) in **one
  transaction** so an auction is all-or-nothing in the DB.

## Why SQLite, not Postgres

One product, one writer, low volume (~one auction per few seconds). SQLite is a single
file, zero-ops, trivially backed up with `.backup`. Postgres earns its place only when
**two+ products** need shared cross-product queries — a post-validation problem.

## Backup

Nightly `sqlite3 cow.db ".backup '/var/backups/cow-$(date +%F).db'"` via a systemd timer
(see `14`). A backup is just a file copy; restore is copy-back.
