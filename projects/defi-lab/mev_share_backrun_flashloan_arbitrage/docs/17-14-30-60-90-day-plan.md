# 17 — 14 / 30 / 60 / 90 Day Plan

Each phase: **Goal / Build / Success / Kill-or-pivot.** Tier tags carried throughout. No
live execution before Day 90, and only then conditionally.

---

## Days 1–14 — V1 shadow scanner stands up (BUILD NOW)

**Goal:** MEV-Share listener + Base/Arbitrum block-delta collectors + Postgres + v2 pool
registry + backrun-v1 producing shadow logs with honest PnL, 24/7 on a VPS.

**Build:**
- Workspace + Docker Compose Postgres + migrations + systemd.
- `core-types`, `config`, `storage` (batched async writer).
- MEV-Share SSE collector + hint backfill; Base + Arbitrum block-delta collectors.
- Decoder → `NormalizedEvent`; v2/sushi-v2 registry + seeding; v2 state reader.
- `strategy-api` trait + `backrun-v1` (detect/score, shadow build).
- PnL accountant + bribe-survival (50/75/90) + flashloan-fee model.
- Fast-estimate sim + replay placeholder interface.
- Risk engine (token denylist, liquidity, freshness).
- Metrics endpoint + tracing JSON + Telegram alerts.
- `ml_features` rows collected (no model).
- Daily cross-chain report.

**Success:** worker runs ≥72h unattended on the VPS without crash/leak; Postgres
accumulates candidates + PnL + features across ≥3 chains; daily report renders per-chain
survival-after-75% counts.

**Kill/pivot:** if you can't reliably ingest events from at least Ethereum + one L2 and
produce graded candidates, fix collectors/decoder before anything else; if the architecture
fights you, simplify (fewer chains) rather than push live.

---

## Days 15–30 — Stable shadow + replay + feature collection (BUILD NOW → first LATER)

**Goal:** weeks of stable multi-chain shadow data; the replay *interface* exercised;
daily PnL/comparison reports trusted.

**Build:**
- Harden collectors (reconnect, dedup, backpressure, block-lag recovery).
- Backfill more history; widen the long-tail pair set per chain.
- Begin **historical replay** (BUILD LATER starts here) to populate
  `ml_features.label_realized` for a sample.
- Daily report upgraded: per-chain/pair median & p95 net, partial vs full-info survival,
  which risk flags kill the most candidates.

**Success:** ≥2 weeks of continuous data; a clear ranked picture of which chains/pairs
produce the most `survives_75` candidates; replay running on a sample.

**Kill/pivot:** if **no** chain/pair shows a coherent, repeatable cluster of
`survives_75` candidates, the edge likely isn't in long-tail v2 backrun — pivot strategy
(OEV/SVR watcher) or chains, *before* investing in accurate sim or execution.

---

## Days 31–60 — Accurate simulation + canary selection prep (BUILD LATER)

**Goal:** prove the fast-estimate is trustworthy where it matters; pick the single
chain+pair niche that would become a live canary.

**Build:**
- **Fork/replay simulator** (revm/reth preferred; Anvil fallback) behind the existing
  `Simulator` trait.
- Predicted-vs-realized scoring; enforce go/no-go metrics (median err ≤10%, p95 ≤20%, sim
  success ≥85%).
- **Redis** *only if* a measured hot-path bottleneck appeared (likely not yet).
- Begin **offline ML**: train a simple model (logistic regression / GBT) on
  `ml_features` to rank candidates / predict false positives — **filtering only, never
  gating risk**.
- Monitoring matured (Grafana optional).

**Success:** one niche (chain+pair+strategy) where shadow predictions clear the go/no-go
bars on accurate replay. ML model improves ranking precision measurably (or is shelved if
it doesn't beat a threshold rule).

**Kill/pivot:** if no niche clears the replay bars, do **not** proceed to live. Either
keep scanning for a better niche or pivot. Accurate replay failing is the cheapest place
to learn the edge is illusory.

---

## Days 61–90 — Tiny live canary, conditionally (DO NOT BUILD YET → gated)

**Goal:** *only if* the niche cleared replay, build the minimum to test it live with
trivial size.

**Build (gated):**
- **Flashloan executor contract** (Balancer-first) with strict guards + Foundry/Anvil fork
  tests; audited by you line-by-line.
- **Live bundle sender** (Ethereum: `mev_sendBundle`) for the one chosen strategy.
- Canary: max tiny notional, daily loss limit, stop-after-2-failures, private submission
  only, kill switch.
- Post-land verification feeding back into the dataset.

**Success:** live revert rate <5%; realized net PnL tracks predictions within tolerance;
no safety incident.

**Kill/pivot:** any of — revert rate ≥5%, realized PnL persistently below predicted, a
safety scare — pulls the canary immediately. Return to shadow/replay. The bond-gated CoW
path or OEV remain alternatives.

---

## Hard gates (summary)

- **Day 14:** 24/7 multi-chain shadow scanner producing graded candidates.
- **Day 30:** repeatable `survives_75` cluster identified, or pivot.
- **Day 60:** one niche clears accurate-replay go/no-go, or no live.
- **Day 90:** tiny live canary *only* if Day-60 passed; else stay shadow.

No step skips the gate before it. Live execution is earned by evidence, not scheduled.
